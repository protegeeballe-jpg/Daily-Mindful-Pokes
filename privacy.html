Faith & Focus: Daily Armor

Effective date: November 11, 2026 · Last updated: November 11, 2026

Privacy Policy

This Privacy Policy explains how Faith & Focus: Daily Armor (the “App”) handles information when you use the web application. The App is maintained by the owner of the public project repository. It is designed to keep routine and writing records in your browser, with optional encrypted GitHub Gist background synchronization and independent manual Google Drive backups.

1. Information stored by the App

The App stores information locally in your browser using browser storage. Depending on the features you use, this can include:

  • App access settings: a salted password-derived verifier for the local app PIN. The App does not store the PIN itself as plain text.
  • Checklist and progress: selected dates, checklist completion states, guided-step states, released-cloud states, completion markers, and confidence points.
  • Location check-ins: when you tick one of the four place checkboxes on the first checklist card, the browser requests a one-time current location. Each successful capture is appended to a date-specific, read-only location history shown in the unlocked Diary. Coordinates can be copied to the device clipboard or opened in Google Maps from the Diary and checklist details. Choosing the map link sends the coordinate query to Google Maps, which handles it under Google's privacy practices. The coordinates, reported accuracy, selected place, and capture time are otherwise stored in separate browser storage on this device. They are not included in either Gist or Google Drive backups and are not removed by the Health Checklist Reset. Your browser or operating system location provider handles the original location request under its own privacy practices.
  • Garden information: your selected tree and flower, planting date, and watering dates.
  • Private writing and voice notes: diary entries, the four checklist reflection fields, and voice recordings. Text is encrypted in browser storage with AES-256-GCM. Voice recordings are encrypted with the same private-writing key before they are stored in this device's IndexedDB database. A separate passphrase is processed with PBKDF2-HMAC-SHA-256 to derive the encryption key. The key is held in memory while the writing is unlocked; the passphrase is not saved by the App.
  • Compressed local cache: to support low-memory mobile devices, local app data is compressed using the native browser `CompressionStream` (gzip) API when you explicitly request a backup.

2. What is and is not encrypted

The app PIN is a local screen gate; it does not encrypt ordinary checklist progress, confidence points, garden information, or location history. Those records remain in browser storage in their normal data format. Private diary entries, checklist reflections, and voice-note audio are encrypted records. Location history is read-only in the App but is not encrypted at rest; anyone with access to the device or its browser storage may be able to access it.

For enhanced session security, the App features an inactivity auto-lock timer (automatically locking private writing after 5 minutes of idle time) and a background visibility lock (immediately dropping active encryption keys from memory when switching apps or locking the device screen).

Choose a strong, memorable private-writing passphrase and keep it safe. The App cannot recover private writing if that passphrase is lost. Clearing browser or site data can permanently remove local records unless backed up through GitHub Gist or Google Drive.

3. Optional cloud backup and synchronization

3.1 Encrypted GitHub Gist synchronization

The App offers a separate, user-initiated GitHub Gist synchronization option through the Faith & Focus Cloudflare Worker. Before upload, the browser combines supported checklist, garden, progress, encrypted Diary, and encrypted voice-note records into a backup payload, compresses it when supported, and encrypts the complete payload with AES-256-GCM. A separate backup passphrase is processed in the browser with PBKDF2-HMAC-SHA-256 (600,000 iterations). The backup passphrase is not sent to Cloudflare or GitHub. If you enable automatic Gist sync, it is stored in this browser's localStorage alongside the Cloudflare Sync Key so the app can authenticate and encrypt background backups without prompting each time. The same backup passphrase is required to decrypt the backup on each device. The App PIN and location history are excluded.

The browser sends the encrypted backup and a separate Cloudflare Sync Key to the Worker over HTTPS. The Worker validates the Sync Key and sends the encrypted file to the configured Gist using a GitHub token held only as a Cloudflare Secret. The GitHub token is never included in browser JavaScript or sent to the browser. Cloudflare processes the request and can observe request metadata and ciphertext; the Worker is designed not to decrypt the backup.

Important Gist visibility note: GitHub secret Gists are unlisted, not private. Anyone who obtains the Gist URL can view its contents. The App therefore encrypts the entire backup before upload; protect the separate backup passphrase. The Gist's revision history may retain earlier encrypted versions.

After you explicitly enable automatic Gist sync on a device, the App checks the Gist after the local app PIN is unlocked, compares the remote ETag and a local data fingerprint, and applies a newer cloud backup only when local records are unchanged. Local changes are saved to this device first, then a background Gist save is debounced until two seconds of inactivity. A conflict pauses automatic overwrite and preserves local data. A best-effort save is attempted when the tab becomes hidden; browsers may suspend or terminate network requests during page close, so reopening the app retries pending work. The Worker compares the ETag observed by the device with the current Gist ETag before accepting an update. This detects stale-device saves in ordinary sequential use; GitHub does not support conditional PATCH writes, so this check alone is not an atomic lock against two saves that occur at nearly the same time.

3.2 Optional Google Drive backup

Optional Google Drive Backup & Restore: The App provides optional, user-initiated cloud backup and restore functionality powered by Google Identity Services (OAuth 2.0).

When you choose to connect your Google account, the App requests permission to access the restricted appDataFolder scope (https://www.googleapis.com/auth/drive.appdata). This scope allows the App to save and retrieve a single compressed backup file (faith-focus-armor-backup.gz) within a private, hidden app folder on your personal Google Drive. User-initiated backups include encrypted Diary text and encrypted voice-note records. Location history remains excluded.

Privacy Guarantees for Google Data:

  • Strictly Manual Sync: Google Drive backup and restore actions remain user-initiated (clicking "Back Up This Device" or "Restore From Drive"). Automatic background synchronization applies only to the separate GitHub Gist option.
  • No Access to General Drive Files: The App cannot read, modify, view, or access any other files, folders, or documents stored in your Google Drive account.
  • No operator-server transmission: Google Drive backup data and Google OAuth tokens are sent directly between your browser and Google Drive over HTTPS, not to the App maintainer's server.
  • PIN Exclusion: Your local device app PIN verifier is intentionally excluded from the backup payload to preserve local access security boundaries.

The App remains fully usable locally without connecting either cloud service. Google Drive remains a separate, independent optional backup and is not replaced or disabled by Gist synchronization.

4. Microphone and voice notes

If you choose the voice-recording control, the browser asks for microphone permission. When you stop recording, the App encrypts the audio with the same AES-256-GCM key used for your private Diary and saves the encrypted recording in this device's IndexedDB storage. Saved recordings appear in the unlocked Diary and remain there after the Health Checklist Reset. They are included as encrypted records in automatic Gist backups when that option is enabled, or in manually initiated Google Drive backups. When Gist sync is selected, the encrypted backup passes through the Cloudflare Worker.

5. Where information is processed

Routine, garden, encrypted-writing, and encrypted voice-note records are processed in your browser and stored on your device. When automatic Gist synchronization is enabled, the complete backup payload is encrypted in the browser before its ciphertext is sent to the Cloudflare Worker and configured GitHub Gist. When you explicitly request a Google Drive backup, the backup is sent directly from your browser to your personal Google Drive account; that Drive backup retains the App's existing field-level Diary and voice-note encryption but does not use the additional whole-payload Gist encryption.

The public website is hosted through GitHub Pages. GitHub provides the website hosting and may process ordinary connection information under its own terms and privacy notices. The App's local records are not sent to GitHub by the App's ordinary local features.

6. Sharing, sale, and advertising

The App maintainer does not sell personal information and does not use App records for advertising. When automatic Gist sync is enabled, the encrypted backup payload and request metadata pass through the configured Cloudflare Worker and the ciphertext is stored in your GitHub Gist; the separate Gist backup passphrase is not sent. When you explicitly request a Google Drive backup, backup data is sent directly to your personal Google Drive. The App does not send plaintext Diary content or the Gist backup passphrase to the maintainer. Location history is excluded from both cloud backup options.

7. Retention and deletion

The Health Checklist Reset clears checklist completion progress and checklist reflection fields for the selected date, and restarts the Garden planting setup. It does not delete your main Personal Diary entries, saved voice notes, or location history. The App provides no control to edit or delete location history. Clearing the site's stored data or browser storage can still permanently remove local records. Optional Google Drive and GitHub Gist backups do not include location history.

8. Children's privacy and family use

The App can be used locally without creating an online account. A parent or guardian should supervise a child's use and should consider what personal or sensitive information is entered into a shared device.

9. Security

The App uses browser-native Web Crypto API encryption (AES-256-GCM) for private writing and for the complete Gist backup payload, PBKDF2-HMAC-SHA-256 key derivation (600,000 iterations), automatic session locking on inactivity or background hide, and a local PIN gate. The Gist backup uses a separate passphrase from the Diary passphrase. HTTPS protects data in transit, but no browser-based safeguard can guarantee protection if a device, browser profile, extension, or operating system is compromised. Keep your device updated, use a device lock, and protect both passphrases and the Cloudflare Sync Key.

10. Changes to this policy

This policy may be updated when the App's features or data practices change. The updated version and effective date will be published on this page.

11. Contact

For questions about this policy or the App's data practices, contact the project maintainer through the project's GitHub issue page. Do not post passphrases, PINs, diary text, access tokens, or other private information in a public issue.
