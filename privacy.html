Faith & Focus: Daily Armor

Effective date: November 12, 2026 · Last updated: November 12, 2026

Privacy Policy

Faith & Focus: Daily Armor (the “App”) is a local-first routine, reflection, and personal garden application. This policy explains what the App stores on your device and what encrypted information is sent to the Cloudflare Worker and Cloudflare KV when you use its automatic vault synchronization. The public app is hosted on GitHub Pages.

1. Account information and cryptographic design

The App asks only for a username and passphrase. It does not request an email address or phone number. The username is normalized in the browser and used to derive a deterministic Vault ID. The passphrase is processed locally using PBKDF2-HMAC-SHA-256 with 600,000 iterations and a username-derived salt. The resulting key material is split into an AES-256-GCM encryption key and a separate Write Token.

The passphrase and AES encryption key are never sent to Cloudflare. The Write Token is sent in an HTTPS request header to authorize vault operations; the Worker stores a SHA-256 hash of that token in the vault's Durable Object storage. The Worker also receives the Vault ID, calendar date, request timing, payload size, and encrypted packet ciphertext. A Vault ID is derived from the username and is not a secret.

The encryption key and raw Write Token are held in browser memory only. They are not stored in localStorage or sessionStorage. The App locks the account after 15 minutes of inactivity and clears the active key and Write Token after pending local writes are flushed.

2. Information stored on your device

Depending on the features you use, the App stores:

  • Daily Health Checklist: dates, all checked and unchecked item states, guided-step unlock states, released-cloud states, completion markers, and confidence points.
  • Personal Diary: diary text and the four private checklist reflection fields.
  • Voice notes: recorded audio and the date, capture time, and technical metadata needed to play the recording.
  • Location check-ins: one-time coordinates, selected place, accuracy, and capture time when you choose a location checkbox. Location history is displayed as a read-only Diary record.
  • Garden: selected tree and flower, planting date, and growth-related state.
  • Encrypted daily packets: a compressed and AES-256-GCM encrypted packet for each calendar date, saved in IndexedDB for local synchronization and optional JSON export.

The App continues to use browser localStorage for some live application records, including routine progress, location records, and Garden state. Those source records are not all encrypted at rest by the App. The daily IndexedDB packet is separately compressed and encrypted before it is used for cloud synchronization. Existing Diary text and voice records also use their own browser-side encryption. Anyone with access to your unlocked device or browser profile may be able to inspect local browser storage; use a trusted device and operating-system screen lock.

3. Daily packet contents and encryption

The App creates one unified bundle for each calendar day using a YYYY-MM-DD date. A bundle includes the date's checklist data, Diary and reflection records, encrypted voice-note records, location tags, and relevant Garden/progress state. The browser serializes the bundle, compresses it with Gzip when the browser supports the existing CompressionStream API, and then encrypts the compressed data with AES-256-GCM using a fresh 96-bit initialization vector for each packet. If Gzip compression is unavailable, the browser records that the packet uses the uncompressed fallback and still encrypts it.

Cloudflare receives encrypted packets only; the Worker does not receive the plaintext Diary, audio, checklist values, or location coordinates. Cloudflare can observe metadata such as Vault IDs, dates, packet sizes, request times, and index timestamps. The App's Worker code validates the request origin, custom application header, Write Token, and 1 MB request limit before handling a packet.

4. Automatic Cloudflare vault synchronization

When you sign in, the browser fetches the Vault ID's date index and compares remote dates with local encrypted packets. Newer cloud packets are downloaded and decrypted in the browser. Local changes are saved as encrypted IndexedDB packets first; after five seconds without another change, the App automatically sends the updated daily packet to the Worker. A best-effort synchronization is also attempted when the page becomes hidden or the browser is closing.

Cloudflare KV stores an index at <Vault_ID>:index with date-to-updatedAt values and a daily packet at <Vault_ID>:<YYYY-MM-DD>. A Durable Object coordinates each vault, serializes updates, and rejects stale base versions to reduce cross-device collisions. If two devices make different changes to the same date, the App pauses the conflicting update and preserves the local packet instead of silently overwriting it. Browsers can suspend network requests during page close, so a hidden-page sync is best-effort rather than guaranteed.

5. Account registration and recovery limits

Passphrases must contain at least 12 characters and no more than 128 characters. The App does not provide email, phone, security-question, or maintainer-assisted recovery. If you forget the passphrase, the encrypted cloud packets cannot be decrypted by the maintainer. Clearing browser data can also remove local copies unless an encrypted JSON export has been saved elsewhere.

A username's vault is established the first time it is claimed. Because the App deliberately has no email, phone, identity provider, or invitation system, the service cannot independently prove who owns an unused username. Another person could claim an unregistered username before its intended owner. Choose a distinctive username and claim it before publicly sharing it.

6. Optional encrypted JSON export and import

Settings allows you to export local encrypted daily packets to a JSON file and import a previously exported file. The file contains packet ciphertext rather than readable Diary content. You must sign in to the same account that created the export to use its contents. The JSON file is a user-controlled fallback; it is not required for automatic synchronization. Protect exported files as sensitive data because they contain encrypted personal records and associated metadata.

The current app does not load Google Drive or GitHub Gist synchronization scripts and does not send data to Google APIs or GitHub Gist. Its configured network connection for automatic vault operations is the Cloudflare Worker.

7. Microphone and voice notes

If you use the voice-recording control, your browser asks for microphone permission. The App encrypts the recorded audio before storing it in IndexedDB. The encrypted voice-note record is also included in that date's encrypted daily packet. Microphone permission and recording are controlled by your browser and operating system. The App does not stream microphone audio to the Worker.

8. Location information

When you choose a location check-in, the browser requests a one-time current location and stores a date-specific record locally. Location records are included inside the compressed and encrypted daily packet for that date, so the cloud copy is encrypted before transmission. The App maintainer and Worker do not receive plaintext coordinates. The App does not provide controls to edit or delete location history; the Health Checklist Reset preserves it. If you open a coordinate in Google Maps or copy it to another service, that action is outside the App and is handled by the selected service.

9. Retention, reset, and deletion

The Health Checklist Reset clears checklist completion progress and reflection fields for the selected date and restarts the Garden planting setup. It preserves the main Personal Diary entries, saved voice notes, and location history. Cloudflare KV retains the encrypted packets and their date index until they are removed by a future deletion feature or by the service operator. The current App interface does not provide a per-account or per-date cloud deletion control. Clearing browser storage does not delete cloud packets.

10. Third-party services and security limitations

The public website is hosted by GitHub Pages. Automatic synchronization uses the configured Cloudflare Worker, Durable Object, and KV namespace. These providers may process connection and service metadata under their own terms. HTTPS protects data in transit, but no browser-based safeguard can guarantee protection if your device, browser profile, extensions, operating system, or the app's hosting origin is compromised. The App's Content Security Policy restricts scripts to the same origin and network connections to the configured Worker; it allows bundled local images, inline styles, local fonts, and Blob audio playback.

11. Children's privacy and family use

The App can be used by families, but a parent or guardian should supervise a child's use and consider what sensitive information is entered into a shared device. Because the same account credentials unlock all records in a vault, do not share a passphrase with anyone who should not be able to read those records.

12. Changes and contact

This policy may be updated when the App's features or data practices change. For questions, contact the project maintainer through the project's GitHub issue page. Do not post passphrases, Write Tokens, diary text, location coordinates, or other private information in a public issue.
